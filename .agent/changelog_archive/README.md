# CHANGELOG 封存

`CHANGELOG.md` 超過封存門檻時，較舊的條目搬到這裡。門檻與流程見 [`commit-and-push` skill](../skills/commit-and-push/SKILL.md) 的「封存門檻」一節。

## 檔名

```
<最舊條目日期>_<最新條目日期>_changelog.md
```

日期為 `YYYYMMDD` 8 位含年份（規範 N-5）。例：`20260827_20260830_changelog.md` 收的是 2026-08-27 到 2026-08-30 之間的條目。

## 封存檔格式

第一行是 H1，接一行說明涵蓋區間，然後照原樣貼入搬過來的條目——**條目本身一個字都不改**，包含日期時間、異動人、範圍、摘要、影響檔案、commit hash。

```markdown
# CHANGELOG 封存：2026-08-27 ~ 2026-08-30

> 本檔為 [`CHANGELOG.md`](../../CHANGELOG.md) 的歷史封存，涵蓋 2026-08-27 至 2026-08-30 共 22 筆紀錄。
> 條目內容與原檔完全一致，未經改寫。

---

## 2026-08-30 22:40 — Claude Code

- **範圍**：規則文件
- **摘要**：...
- **影響檔案**：...
- **commit**：`917efe1`

---
```

## 為什麼不自動化

封存會大幅改寫 `CHANGELOG.md` 的開頭。若綁進 commit 流程自動執行，等於在 commit 進行中改動一個已經 `git add` 過的檔案，出錯時很難分辨是封存造成的還是原本的變更造成的。因此只在 pre-commit hook 印提醒，實際搬移由人或 agent 明確地做一次，並在該次 commit 的 CHANGELOG 條目裡寫清楚封存了哪個區間。

## 目前狀態

尚未觸發過封存，本目錄除本說明外沒有其他檔案。
