#### 2. 回答品質 ( RAGAS )

傳統的 NLP 評測指標（如 BLEU、ROUGE）只能比對生成文字與標準答案的比對相似度，無法判斷「檢索出來的資料對不對」或是「模型有沒有憑空捏造（幻覺）」。

RAGAS 的核心概念是使用 **LLM-as-a-Judge（高階大語言模型擔任裁判）**，將 RAG 拆解為「檢索元件 (Retriever)」**與**「生成元件 (Generator)」，並從以下核心維度進行獨立量化打分

#### 1. 評估「生成模組 (Generator)」品質

**Faithfulness (忠實度 / 幻覺率)**：評估 SLM/LLM 生成的回答是否**完全基於**檢索到的資料。得分低代表模型開始「胡說八道」或出現幻覺。

**Answer Relevance (回答相關性)**：評估模型給出的回答是否精準回應了使用者的提問，有無答非所問或給出大量冗餘廢話。

#### 2. 評估「檢索模組 (Retriever)」品質

**Context Precision (檢索精確度)**：評估向量庫抓出來的資料區塊 (Chunks) 中，有用的資訊是否排在前面，有沒有混入不相關的雜訊。  

**Context Recall (檢索召回率)**：評估回答問題所需的關鍵知識，有多大比例被成功從向量庫中檢索出來。

#### 3. 搭配標準答案 (Ground Truth) 的指標

**Factual Correctness (事實正確性)**：將生成的回答與專家寫好的標準答案拆解為獨立事實，比對兩者一致性。  

**Semantic Similarity (語意相似度)**：評估生成回答與標準答案的向量語意距離。

### RAGAS (Retrieval Augmented Generation Assessment) 技術與評測手冊

一、 RAGAS 簡介與定位

**定義**：專門用於**自動化評估 RAG (檢索增強生成) 系統**與**語言模型生成品質**的開源評測框架。  

**核心機制**：採用 **LLM-as-a-Judge（大語言模型擔任裁判）**，將非結構化的生成文字拆解為獨立命題（Claims）與語意向量，進行量化打分（分數介於 `0.0 ~ 1.0`）。  

**學術地位**：目前頂級 NLP/AI 期刊與會議（ACL、EMNLP、IEEE、MDPI）評估 RAG 與邊緣端 SLM 的**標準主流工具**。

二、 核心評估指標 (Core Metrics)

RAGAS 將系統拆解為「檢索端 (Retriever)」與「生成端 (Generator)」進行獨立診斷：

**Faithfulness (忠實度 / 幻覺率)**: 評估對象為生成端 (SLM)。其定義與物理意義是用於評估回答是否完全基於檢索到的 Context，有無模型憑空捏造的內容（測幻覺）。必要輸入欄位包含 `response` 與 `contexts`。 

**Answer Relevance (回答相關性)**: 評估對象為生成端 (SLM)。其定義與物理意義是用於評估生成內容是否切中使用者問題，有無冗餘廢話或答非所問。必要輸入欄位包含 `user_input` 與 `response`。  

**Context Precision (檢索精確度)**: 評估對象為檢索端 (Vector DB)。其定義與物理意義是用於評估向量庫抓出的切塊 (Chunks) 中，有用資訊是否排在前面。必要輸入欄位包含 `user_input`、`contexts` 與 `reference`。  

**Context Recall (檢索召回率)**: 評估對象為檢索端 (Vector DB)。其定義與物理意義是用於評估回答所需的關鍵資訊中，有多少比例被成功檢索出來。必要輸入欄位包含 `contexts` 與 `reference`。  

**Factual Correctness (事實正確性)**: 評估對象為端到端品質。其定義與物理意義是透過自然語言推論 (NLI) 比對生成的回答與專家標準答案 (Ground Truth) 的事實重疊度。必要輸入欄位包含 `response` 與 `reference`。  

**Semantic Similarity (語意相似度)**: 評估對象為端到端品質。其定義與物理意義是利用 Cross-Encoder 向量模型計算回答與標準答案之間的語意距離。必要輸入欄位包含 `response` 與 `reference`。

### 🔬 本次柑橘病蟲害 RAGAs 評估實驗記錄 (Experiment Run Specification)

#### 1. 實驗環境與模型配置

- **被評測端側 SLM**：`citrus-slm` (本機端側小模型，透過 Ollama API 本地推理，模擬手機離線環境)
- **檢索架構**：Pocket Hybrid RAG (N-Gram 關鍵字 + 128 維向量余弦相似度，Top-K = 2，閾值 = 0.20)
- **知識庫來源**：`plant_diseases_kb.json` (8 筆柑橘重點病蟲害)
- **評估裁判 LLM**：**Google Gemini 2.5 Flash** (`gemini-2.5-flash`)
- **裁判向量模型**：**Google Gemini Embeddings** (`models/gemini-embedding-001`，維度 3072)
- **評估框架**：RAGAs v0.4.3

#### 2. 測試資料集結構 (12 題分組)

- **【IN_DOMAIN】柑橘病蟲害與用藥核心題 (8 題)**：
    1. 潰瘍病火山口特徵與銅劑/防風防治
    2. 潰瘍病禁用大生粉（殺真菌劑對細菌無效）鑑別
    3. 黑點病枯枝產孢與清園禁堆樹下原則
    4. 油斑病葉背氣孔侵入與由下往上噴藥技巧
    5. 煤煙病治煤先治蟲與窄域油物理洗滌
    6. 潛葉蛾捲葉後阿巴汀內滲補救
    7. 小黃薊馬採收前安全採收期 (PHI) 規範
    8. 介殼蟲窄域油物理窒息與天敵澳洲瓢蟲
- **【CROSS_DOMAIN】跨作物干擾題 (2 題)**：
    1. 水稻稻熱病紡錘形病斑與三賽唑防治
    2. 茶樹茶輪斑病同心輪紋與通風排水

    1. 程式撰寫 (Python Quick Sort 拒答)
    2. 天氣查詢 (台北天氣與雨具拒答)

#### 3. 4 大黃金指標與計算函式

- **Faithfulness (回答真實度 / 防幻覺)**：`from ragas.metrics import Faithfulness`
    - 計算回答中的陳述句有多少比例能由檢索 Context 完全推導證實，杜絕模型胡編農藥與病徵。
- **Answer Relevancy (回答相關性)**：`from ragas.metrics import AnswerRelevancy`
    - 裁判根據 SLM 回答反推生成 3 個問題，並以 `gemini-embedding-001` 計算與原始問題的余弦相似度。
- **Context Precision (檢索精確度)**：`from ragas.metrics import LLMContextPrecisionWithReference`
    - 評估檢索出的 Top-2 文本中，真正有用的段落是否排在最前面 (Top-1 命中加權)。
- **Context Recall (檢索召回率)**：`from ragas.metrics import LLMContextRecall`
    - 評估專家標準答案中的事實要點，有多大比例被檢索文本完整涵蓋。

#### 4. 首次實測結果與逐題深入診斷 (Baseline Run & Error Analysis)

- **【實測核心優勢 (Strengths)】**：
    1. **邊界防禦與防幻覺拒答率 100% (OOD Safety)**：面對 Python 寫程式 (Q11) 與台北天氣查詢 (Q12)，模型在未命中知識庫時均堅定禮貌拒答，展現極佳角色邊界自覺。
    2. **核心病害診斷精準**：茂谷柑潰瘍病 (Q1) 精確診斷並命中 77% 氫氧化銅；小黃薊馬 (Q7) 命中安全採收期 6 天；介殼蟲 (Q8) 命中 95% 窄域油物理窒息機制。
- **【發現之關鍵瓶頸 (Weaknesses & Bottlenecks)】**：
    1. **Prompt 複誦問題 (Prompt Echoing)**：Q3 (黑點病枯枝) 與 Q9 (水稻) 出現模型原樣抄寫 Prompt 後未作答即結束之現象（端側 SLM 注意力衰退）。

    3. **跨作物強行套用 (Cross-Domain Interference)**：Q10 茶樹問題檢索到柑橘油斑病，模型強行關聯並捏造「茶树柑橘病害」與「代森錳丹」。
- **【後續微調 (SFT) 與 RAG 優化策略】**：
    1. **Prompt 結尾錨點 (Anchor Token)**：在 Prompt 尾部固定加入 `【專家診斷與建議】：` 強制模型直接進入解答模式。
